# ไปไกลให้คุ้ม — Web Application

Prototype สำหรับ **Track 1: Data to Solution** (CAMT x AIAT AI Innovation Hackathon)
เปลี่ยนแหล่งท่องเที่ยวนอกเมืองในชุดข้อมูล ททท. ให้เป็น **ทริปวันเดียว (pod)** ที่บอกล่วงหน้าว่า
*รู้อะไรแน่ ๆ* และ *ยังไม่รู้อะไร* แทนที่จะซ่อนช่องว่างของข้อมูล

## สิ่งที่ระบบทำ

| # | ระบบ | อยู่ที่ไหน |
|---|---|---|
| 1 | **บันทึกลงฐานข้อมูลไฟล์เดียว** — ทุกการบันทึกจากหน้าเว็บลง `sources/database-attraction.json` โดย seed จาก `sources/attraction.json` **ครั้งแรกครั้งเดียว** | `server/db.js` |
| 2 | **ระบบวางแผน** — Pre-trip Briefing, checklist, ประมาณเวลา, แผนสำหรับรถ EV | `server/engine.js` → `buildBriefing()` |
| 3 | **ระบบ feedback loop** — หลังทริประบบเลือก 3 คำถามที่ "ถามแล้วคุ้มที่สุด" เอง คำตอบกลายเป็นข้อมูลชั้น D และวนกลับไปปรับอันดับการแนะนำ | `topQuestions()` + `POST /api/feedback` |
| 4 | **ระบบแนะนำสถานที่** — rule-based scoring 8 ปัจจัย พร้อมเหตุผลที่อธิบายได้ทุกข้อ | `recommend()` |
| 5 | **ระบบยกระดับชั้นข้อมูล** — แดชบอร์ด ททท. ยกชั้น D→B และ B→A ได้ มีผู้รับผิดชอบทุกครั้ง และถอนคืนได้ | `server/promote.js` |
| 6 | **แผนที่ OpenStreetMap** — ลำดับการแวะ + ระยะถนนจริงและเวลาขับจาก OSRM | `server/route.js` → `src/components/OsmMap.jsx` |
| 7 | ธีม **ส้ม / ขาว / ดำ** | `src/styles.css` |

## หลักฐาน 4 ชั้น (ตามกติกา Track 1)

| ชั้น | ที่มา | สีในหน้าจอ |
|---|---|---|
| **A** | ฟิลด์ต้นทางของ ททท. (`ATT_FEE_TH`, `ATT_START_END`, …) | เขียว |
| **B** | AI สกัดจากข้อความต้นฉบับ — **กดดูประโยคที่ยกมาได้ทุกครั้ง** | เหลือง |
| **D** | ผู้ใช้รายงานหลังไปจริง — ต้องมีคนตอบตรงกัน 2 คนจึงนับเป็นข้อมูลยืนยัน และ**ไม่ทับชั้น A** (ถ้าขัดกันแสดงทั้งคู่) | ฟ้า |
| **C** | ไม่พบในชุดข้อมูล — ระบบบอกตรง ๆ ว่าไม่รู้ ไม่เดาแทน | เทา |

### การยกระดับชั้น (Evidence Tier Promotion)

ข้อมูลไม่ได้ติดอยู่ที่ชั้นเดิมตลอดไป — แดชบอร์ด ททท. มี "โต๊ะตรวจ" ให้ไต่ขึ้นทีละชั้น

| ยก | เงื่อนไข | ใครทำ | ผลที่เกิด |
|---|---|---|---|
| **D → B** | ผู้ไปจริงรายงานค่าเดียวกันครบ **2 คน** และช่องนั้นยังไม่อยู่ชั้น A/B | ผู้ตรวจข้อมูล | รายงานของผู้ใช้กลายเป็นหลักฐานที่ตรวจแล้ว |
| **B → A** | ช่องนั้นอยู่ชั้น B อยู่แล้ว (AI สกัด หรือรับรองมาจากชั้น D) | เจ้าหน้าที่ ททท. | รับเข้าเป็นระเบียนทางการของ ททท. |

กติกาที่ระบบบังคับทุกครั้ง

1. **ต้องมีผู้รับผิดชอบ** — ยกระดับโดยไม่ระบุชื่อไม่ได้ (API ตอบ 400)
2. **แช่แข็งหลักฐาน** — เก็บหลักฐานที่ผู้ตรวจเห็น ณ วินาทีที่กด ไว้ในรายการนั้นเลย ตรวจย้อนหลังได้
3. **ถอนคืนได้เสมอ** — ถอนแล้วข้อมูลกลับไปชั้นเดิมทันที แต่**ไม่ลบประวัติ** (ทำเครื่องหมาย `revokedAt`)
4. **ไม่ข้ามชั้น** — ยกจาก C หรือ D ไปชั้น A ตรง ๆ ไม่ได้ ต้องผ่าน B เสมอ

เมื่อยกระดับแล้ว ค่าใหม่จะไหลเข้าทุกระบบทันที — ความครบของข้อมูล, Trip Risk Badge,
คะแนนการแนะนำ, Pre-trip Briefing และคำถามหลังทริป (ช่องที่รู้แล้วจะไม่ถูกถามซ้ำ)

สมุดบันทึกทั้งหมดอยู่ใน `promotions` ของ `sources/database-attraction.json`

## โครงสร้างโฟลเดอร์

```
web/
├── sources/
│   ├── attraction.json            ← ข้อมูลตั้งต้น ททท. (อ่านอย่างเดียว)
│   ├── faraway_pods.json          ← ชุดทริปที่คำนวณไว้ (อ่านอย่างเดียว)
│   └── database-attraction.json   ← ฐานข้อมูลของแอป (สร้างอัตโนมัติ + เขียนทุกครั้งที่บันทึก)
├── server/                        ← Express API + seed + engine
└── src/                           ← React (Vite)
```

npm install

เปิด <http://localhost:5173>

คำสั่งอื่น

```bash
npm run seed      # สร้าง database-attraction.json (ข้ามถ้ามีอยู่แล้ว)
npm run reseed    # สร้างใหม่ทับของเดิม — ข้อมูลที่ผู้ใช้บันทึกไว้จะหายทั้งหมด
npm run server    # รันเฉพาะ API
npm run web       # รันเฉพาะหน้าเว็บ
```

## เส้นทาง API

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| GET | `/api/meta` | ข้อมูลตั้งต้นของแอป (จังหวัด, ฟิลด์, ชั้นข้อมูล) |
| GET | `/api/stats` | สถิติรวม + ความครอบคลุมแยกที่มา |
| GET | `/api/recommend` | ระบบแนะนำ (`province`, `hours`, `maxKm`, `interests`, `ev`, `rangeKm`, `avoidUnknown`) |
| GET | `/api/pods/:id` | รายละเอียดชุดทริป + badge + 3 คำถามที่ควรถาม |
| GET | `/api/plan/preview/:podId` | Pre-trip Briefing (ยังไม่บันทึก) |
| POST | `/api/plans` | บันทึกทริป → เขียนลงไฟล์ |
| GET/PATCH/DELETE | `/api/plans/:id` | จัดการทริป |
| GET | `/api/questions/:podId` | 3 คำถามที่คุ้มที่สุดของชุดนั้น |
| POST | `/api/feedback` | ส่งคำตอบหลังทริป → สร้างข้อมูลชั้น D |
| GET | `/api/gaps` | Gap Queue สำหรับ ททท. |
| GET | `/api/promotions/queue` | คิวช่องที่พร้อมยกระดับ (`to=B` หรือ `to=A`, `province`, `limit`) |
| GET | `/api/promotions` | สมุดบันทึกการยกระดับทั้งหมด |
| POST | `/api/promotions` | ยกระดับ 1 ช่อง — `{siteId, field, to, by, note}` (`by` บังคับ) |
| POST | `/api/promotions/:id/revoke` | ถอนการยกระดับ — `{by, reason}` |
| GET | `/api/promotions/history/:siteId/:field` | ประวัติการยกระดับของช่องนั้น + ตรวจว่ายกต่อได้ไหม |
| GET | `/api/route/:podId` | ลำดับการแวะ + ระยะถนนจริง (`roads=false` เพื่อใช้เส้นตรงอย่างเดียว) |

## ข้อจำกัดที่ระบบประกาศเอง

1. **ระยะทาง** — ชุดข้อมูล ททท. มีแค่พิกัด ระบบจึงคำนวณเส้นตรงเองเสมอ ส่วน "ระยะถนนจริง"
   และ "เวลาขับ" บนแผนที่ขอจาก **OSRM (OpenStreetMap)** ตอนเปิดหน้า — ถ้าติดต่อไม่ได้
   ระบบจะบอกตรง ๆ แล้วถอยไปแสดงเส้นตรง (เส้นบนแผนที่เปลี่ยนเป็นเส้นประ) ไม่เดาตัวเลขถนนขึ้นมาเอง
   ตั้งเซิร์ฟเวอร์อื่นได้ด้วย `OSRM_BASE` และปรับ timeout ด้วย `OSRM_TIMEOUT_MS` (ค่าเริ่มต้น 6000 ms)
2. `NO_FOOD` / `NO_CHARGER_IN_DATA` = **ไม่พบในชุดข้อมูล ททท.** ไม่ได้แปลว่าไม่มีอยู่จริง
3. เกณฑ์ pod (รัศมี, จำนวนแหล่ง, จำนวนหมวด) และตัวคูณระยะถนน 1.3 เป็น **ค่าที่ทีมตั้งเอง** — ปรับได้
4. ตัวสกัดชั้น B เป็น rule-based + ยกประโยคต้นฉบับ ไม่ได้สร้างข้อความใหม่ จึงไม่มีการแต่งข้อเท็จจริง
5. ยังไม่ได้เชื่อมข้อมูลจุดชาร์จ EV จากแหล่งภายนอก — ต้องตรวจสิทธิ์การใช้งานก่อนตามกติกา Track 1
6. **การยกระดับชั้นข้อมูลยังไม่มีระบบล็อกอิน** — ช่อง "ผู้รับผิดชอบ" เป็นการพิมพ์ชื่อเอง
   ถ้านำไปใช้จริงต้องต่อกับระบบยืนยันตัวตนของ ททท. ก่อน
7. **ลำดับการแวะ** จัดด้วย nearest-neighbour + 2-opt บนระยะเส้นตรง ไม่ใช่การหาเส้นทางที่สั้นที่สุดจริง
   และยังไม่คิดเรื่องเวลาเปิด-ปิดของแต่ละแหล่ง
